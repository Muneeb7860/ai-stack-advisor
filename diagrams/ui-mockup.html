4 Sticky nav bar (FR-24) — every one of the 16 sections is a jump-link, so the page never feels like a single unmanageable scroll despite its real length.

Page 2b — Guided Input Mode now in implementation — see index.html
The click-through prototype that seeded this: design-sketch-v3-guided.html — mode picker, 6-question wizard, one real "skip compliance if audience is internal" branch. Its progressive-reveal results screen (summary + 4-cell glance strip, sections collapsed behind "Show") is NOT what got built — see annotation 15 below. design-sketch-v2.html is the earlier tabbed-results direction, kept for history only — don't build against either sketch file directly, both predate the locked decisions.
12 Landing decision (made 2026-08-08, see KICKOFF_BRIEF.md): the mode picker is equal-weight — guided mode is not the default, free text is not the default, both are offered up front with neither pre-selected.
13 Zero-backend-dependency by design, matching NFR-5: the wizard's branching (skip/show questions, chip and radio state) is client-side logic in the same class as detectSignals(). Wizard answers synthesize a natural-language paragraph fed through the existing detectSignals() unchanged — no parallel signal-mapping code path. No point in the flow structurally needs a server round-trip; "Refine with AI" remains an optional per-card enhancement layered on top afterward, same as free-text mode already has.
14 Skip logic ships with exactly the one case proven in the sketch (compliance question skipped when audience=internal) — no speculative additional branching added.
15 Decision made 2026-08-08, reversing the sketch's own concept: both the guided and free-text paths render through the existing 14-section full result view (frame 02), not the sketch's progressive-reveal screen. The sketch file itself was left as-is for historical reference — its results screen shows a different, superseded direction, not the current spec.
